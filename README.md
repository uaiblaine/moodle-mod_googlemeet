# Google Meet™ for Moodle

Activity module that lets teachers schedule Google Meet rooms from Moodle, sync the meeting recordings
from Google Drive and turn them into study material for students: per-recording pages with chapters,
AI summaries, practice questions, materials and viewing progress.

> This is a fork of [hyukudan/moodle-mod_googlemeet](https://github.com/hyukudan/moodle-mod_googlemeet),
> itself a fork of [ronefel/moodle-mod_googlemeet](https://github.com/ronefel/moodle-mod_googlemeet),
> for **Moodle 5.2 and 5.3**. The component name is still `mod_googlemeet`.

## Features

**Live sessions**
- Create a Google Meet room and Google Calendar event from the activity form (the event is created
  in the calendar of the teacher's linked Google account).
- One-off or recurring sessions (daily/weekly), exclusion periods (holidays) and cancelled dates
  with a reason.
- "Enter room" button that becomes active shortly before each session, upcoming-sessions block,
  Moodle calendar events with a "Go to classroom" action, and an "Add to my calendar" link
  (`.ics` file and Google Calendar template).
- Email/popup and Moodle app push reminders before each session (two configurable reminders).
- Edits to name, dates or recurrence are pushed to the Google Calendar event in the background.
- Optional real attendance read from the Google Meet REST API, with a per-session report and
  CSV/XLSX export (off by default, see [Limitations](#known-limitations)).

**Recordings**
- Manual or automatic sync of the recordings from the organiser's Google Drive, matched by meeting
  name (or a custom filter), with retries and a teacher alert if a recording never appears.
- List or card view, search (title, topics, summary; notes and transcript for teachers), topic
  filter, pagination, show/hide per recording, rename, trash with restore and configurable
  retention.
- "Notes by Gemini" documents generated by Google Meet are imported, cleaned and shown in a Notes tab.
- Per-recording hub: embedded Drive player, chapters and clickable timestamps, summary, key-points
  checklist, transcript, notes, materials (file attachments) and practice questions, with
  previous/next navigation.
- Per-student viewing progress ("Mark as viewed", partial/complete), a teacher report on viewing
  and practice per student (CSV/XLSX), and custom completion rules (watch N recordings, watch X %
  of recordings, answer N practice questions).
- Optional "new recording available" notifications that learners subscribe to.

**AI (Google Gemini, optional)**
- Summary, key points, topic tags and timestamped chapters for each recording, in the language of
  the recording.
- Practice questions generated into the course question bank as drafts; teachers review and
  publish, students practise one question at a time with feedback (formative, no grade).
- Teacher review step before AI content is shown to students (on by default).
- Background processing via scheduled/adhoc tasks, automatic retries on transient errors and
  model fallback.

**Other**
- Moodle app support (activity, recordings, AI content, materials, practice).
- Backup/restore and duplication (including the practice questions), course reset, privacy API
  (export/delete), admin sync status page.

## Requirements

- Moodle 5.2 or 5.3 (`requires = 2026042000`, `supported = [502, 503]`). Moodle 5.1 and older
  are not supported by 2.30.1+uai.1 and later.
- PHP 8.3 or later (the Moodle 5.2 minimum).
- A Google account (Google Workspace recommended) that organises the meetings and owns the recordings.
- A Google Cloud project with an OAuth 2.0 client.
- Moodle cron running **every minute** (sync, Calendar updates and AI run as adhoc tasks).
- Optional: a Gemini API key (AI features) and [yt-dlp](https://github.com/yt-dlp/yt-dlp)
  (fast subtitle extraction).

## Installation

1. Copy the plugin to `public/mod/googlemeet`, or install it from the plugins directory.
2. Visit *Site administration > Notifications* (or run `php admin/cli/upgrade.php`).
3. Configure the Google OAuth 2 service and select it in the plugin settings
   (*Site administration > Plugins > Activity modules > Google Meet*, setting `issuerid`).

## Google Cloud setup

1. Create (or choose) a project in the [Google Cloud console](https://console.cloud.google.com/).
2. Enable the APIs the plugin calls:
   - **Google Calendar API** (create and update the meeting event / Meet room),
   - **Google Drive API** (list recordings, transcripts and "Notes by Gemini" documents, set
     sharing),
   - **Google Meet REST API** only if you enable attendance.
3. Configure the OAuth consent screen and create an **OAuth client ID** of type *Web application*.
   Add `https://<your-moodle>/admin/oauth2callback.php` as an authorised redirect URI.
4. In Moodle, go to *Site administration > Server > OAuth 2 services*, create a **Google** service
   with that client ID and secret, and select it in the plugin's `issuerid` setting.
5. Teachers link their Google account from the activity page. The account that created the
   activity (the organiser, `creatoremail`) is the one whose Drive is synced.

**Scopes requested** (in addition to the basic `openid profile email` of the Moodle Google issuer):

| Scope | Why |
|---|---|
| `https://www.googleapis.com/auth/drive` | Find the recordings, transcripts and notes in the organiser's Drive (they are created by Meet, not by this app, so a narrower scope cannot see them), download transcripts, and grant link sharing on recordings. |
| `https://www.googleapis.com/auth/calendar.events` | Create the meeting event with its Meet room, and update or delete it when the activity changes. |
| `https://www.googleapis.com/auth/meetings.space.readonly` | Only while attendance is enabled for the site: read conference records and participants. |

A sensitive/restricted scope such as `drive` may require Google's app verification if the consent
screen is external; an *Internal* consent screen in a Google Workspace domain avoids that.

**Recording sharing.** With `makerecordingspublic` on (default), each synced recording is shared
on Drive as **"anyone with the link can view"** so enrolled students, who are not the Drive owner,
can play the embedded video. Anyone who obtains the link can watch it without logging in to Moodle.
Turning the setting off keeps recordings private, but then only Google accounts with explicit
access (normally just the organiser) can play them.

## Gemini setup and data sent

1. Get an API key from [Google AI Studio](https://aistudio.google.com/app/apikey).
2. In the plugin settings enable AI, paste the key and choose a model (default
   `gemini-3.5-flash`, automatic fallback to `gemini-3.1-flash-lite`).
3. Optionally enable automatic analysis of new recordings, adjust the safety threshold
   (`aisafetythreshold`) and decide whether AI content needs teacher review (`requireaireview`).
4. Set the **teaching context** (`aicontext`, see below).

What is sent to the Gemini API (Google's terms for the key's project apply; check whether your
tier allows Google to use the data):
- The recording **transcript** (Drive transcript, auto-generated subtitles or text pasted by the
  teacher), the recording title and duration, and the teaching context.
- As a **last resort**, when no transcript or subtitles exist, the **recording video** is
  downloaded from Drive and uploaded to the Gemini File API; the uploaded file is deleted after
  the analysis.
- For practice questions, the transcript again.

Transcripts and videos can contain participants' names and voices. Inform users accordingly; the
privacy provider declares these flows.

### Teaching context (`aicontext`)

A short free-text description of the kind of classes on the site (subject area, audience, exam or
qualification) added to every Gemini prompt so summaries, topics, chapters and questions use the
right focus and vocabulary. Default: `Online training classes`. Leave it empty to send no context.
Example: `Live preparation classes for public-sector competitive exams (law and administration)`.

Output language follows the recording (analysis) or the requested course language (questions,
chapters), independently of this setting.

### yt-dlp (optional)

When available, yt-dlp fetches Google Drive's auto-generated subtitles (a few hundred KB) instead of
downloading the whole video. Install it to a persistent location that only administrators can write
(never `/tmp`), and set `ytdlppath` or put it in the PATH of the web and cron user:

```bash
curl -sL https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp -o /usr/local/bin/yt-dlp
chmod +x /usr/local/bin/yt-dlp
```

`subtitlelanguage` (default `es`) selects the subtitle track.

## Scheduled tasks

| Task | Default schedule | Purpose |
|---|---|---|
| `\mod_googlemeet\task\notify_event` | every 5 min | Session reminders |
| `\mod_googlemeet\task\process_ai_analysis` | every 10 min | Queued AI analyses, stuck-analysis cleanup |
| `\mod_googlemeet\task\process_autosync` | every 15 min | Automatic recording sync after each session |
| `\mod_googlemeet\task\check_stale_recurrence` | Mondays 04:00 | Alert admins about recurrences with no recordings for N weeks |
| `\mod_googlemeet\task\purge_trash` | daily 03:xx | Purge recordings a teacher trashed, after `trashretentiondays` |
| `\mod_googlemeet\task\fetch_attendance` | every 30 min | Read attendance (no-op while attendance is off) |

Adhoc tasks: background Drive sync, recording enrichment (notes/transcripts), video analysis,
question generation, new-recording notifications, Calendar update and delete. Run cron every minute
so that teachers do not wait for these.

CLI scripts (run from the Moodle root): `cli/process_transcripts.php` (bulk subtitles + analysis),
`cli/backfill_chapters.php`, `cli/backfill_questions.php` and `cli/cleanup_orphans.php` (dry run by
default). Use `--help` on each.

| `mod/googlemeet:removerecording` | editing teacher, manager | Trash and delete recordings |
| `mod/googlemeet:generateai` | editing teacher, manager | Run and edit AI analysis |
| `mod/googlemeet:managequestions` | teacher, editing teacher, manager | Generate, review and publish practice questions |
| `mod/googlemeet:subscriberecordings` | student, teacher, editing teacher, manager | Subscribe to new-recording notifications |
| `mod/googlemeet:viewreports` | teacher, editing teacher, manager | Viewing/practice report and attendance (read and download) |
| `mod/googlemeet:manageattendance` | editing teacher, manager | Link/unlink Meet participants to users, refetch a session's attendance |

## Privacy and GDPR

- Stored in Moodle: recordings metadata, AI analysis, per-user viewing progress, practice answers,
  notification subscriptions and sent-reminder log, attendance read from Google Meet, and user
  preferences (last jump point, key-points checklist). All are covered by the privacy provider
  (export and deletion) and by course reset where applicable.
- Sent to Google: Drive and Calendar requests on behalf of the linked teacher account; Gemini as
  described above; Meet REST requests when attendance is on.
- Recordings shared "anyone with the link" are reachable outside Moodle (see above).
- Practice answers, viewing progress and attendance are personal data; set your site's data
  retention policy accordingly.

## Optional integrations

The plugin works without any of these; they are detected at run time.

- **Question publish check**: if a local plugin provides `local/questions/fugaslib.php` with the
  functions `fugas_campos_pregunta()` and `fugas_exigir_limpia()`, practice questions are validated
  by it before they are published. Without it the check is skipped (a debugging notice is shown).
- **Email wrapper**: if a class `\local_achievements\email_template` exists, the new-recording email
  body is wrapped with its `wrap()` method; otherwise the plain plugin template is used.

## Known limitations

- The embedded Google Drive player does not expose the playback position, so viewing progress is
  based on time the page is visible and "Continue at mm:ss" is only the last point the user jumped to.
- Chapter jumps use the Drive preview `?t=` parameter, which is undocumented and may change.
- Recordings are matched by meeting name in the organiser's Drive; renamed recordings need a custom
  filter.
- Attendance needs the Google Meet REST API, the organiser account to re-link with the extra scope,
  and a Google account type that exposes conference records (it may not work with consumer Gmail
  accounts). Google keeps those records for about 30 days, and name matching to Moodle users is
  heuristic (manual linking is available).
- "Mark as viewed" is a declaration by the student, not proof of viewing.

## Upgrading

- Back up the database and the `mod/googlemeet` folder, replace the code and run
  `php admin/cli/upgrade.php`, then purge caches. If OPcache runs with
  `opcache.validate_timestamps=0`, reset it as well.
- Upgrading from the upstream ronefel plugin works in place (same component); review the new
  settings afterwards. There is no way back to the upstream version once upgraded.
- 2.30.0: AI content needs teacher review by default (`requireaireview`); existing analyses are
  marked as reviewed. Existing items in the trash are never purged automatically.
- Do not deploy development files (`tests/`, `.github/`, local notes) to production if you copy the
  working tree.
